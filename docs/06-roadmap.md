# Дорожная карта

Спешки нет — строим сразу правильно, без миграций посреди живых клиентов. Но правило прежнее: продавать начинаем, как только работает ядро, а не когда готово всё.

## Этап 1 — ядро (боты + база)

- [ ] VPS, домен, Caddy + HTTPS, docker-compose
- [ ] Postgres со схемой из 08-data-model.md
- [ ] Telegram-бот: диалог записи (конечный автомат), подтверждения
- [ ] Воркер: каскад напоминаний (T−24/T−3, догон SMS), лист ожидания
- [ ] SMS-агрегатор подключён, статусы доставки пишутся в message_log
- [ ] Реактивация: TG-контур + SMS-волны порциями с отпиской
- [ ] Мониторинг (Uptime Kuma) + ночные бэкапы в S3 РФ
- [ ] Демо-салон с фиктивными услугами — продающий артефакт

**Выход:** система работает без кабинета; демо, куда владелец записывается за 30 секунд. С этого момента начинаются продажи (список 30 контактов, касания, спеццена первым за отзыв).

## Этап 2 — кабинет владельца v1 (только чтение)

- [ ] Auth (argon2, сессии, роли), изоляция salon_id + тест на неё
- [ ] Дашборд: визиты, % подтверждений, «возвращено ≈ N ₽»
- [ ] Журнал записей со статусами
- [ ] Месячный отчёт: расчёт + страница + PDF

**Выход:** кабинет показываем на продажах; первый клиент получает первый отчёт с реальными цифрами (главный продающий артефакт + видеоотзыв).

## Этап 3 — админка

- [ ] Онбординг-форма: новый салон ≤ 15 минут
- [ ] Список салонов: статус, здоровье, расход SMS против лимита
- [ ] Логи сообщений и ошибок, feature-флаги
- [ ] Биллинг абонентки

**Выход:** подключение клиентов не требует ручной работы в базе; берём поток внедрений.

## Этап 4 — кабинет v2 (редактирование) = полноценная CRM

- [ ] Ручное добавление записи (телефонные — в тот же каскад)
- [ ] Управление услугами, циклами, текстами, часами
- [ ] База клиентов: «спящие», исключение из рассылок

**Выход:** для салонов без YCLIENTS мы — их единственная система. Отток падает: уйти = потерять кабинет с базой.

## Этап 5 — MAX + интеграции

- [ ] MAX-бот: верификация (самозанятость), вебхуки, сертификат Минцифры на сервере
- [ ] Каскад TG → MAX → SMS по приоритету салона
- [ ] Синхронизация YCLIENTS ⇄ Postgres для салонов, где она есть

**Выход:** покрытие аудитории без Telegram, SMS-расходы падают.

## Разделение ролей

| Зона | Брат (AI-автоматизация) | ИБ-партнёр |
|---|---|---|
| Backend: боты, диалоги, воркер, LLM, кабинет | ✔ основная | ревью |
| Инфраструктура: VPS, Caddy, бэкапы, мониторинг | — | ✔ основная |
| Безопасность: auth, изоляция тенантов, секреты, аудит | консультации | ✔ основная |
| Продажи: списки, касания, созвоны, договоры | помощь на демо | ✔ основная (опыт переговоров) |
| Отчёты клиентам | генерация | упаковка и отправка |

Продажи закреплены за одним человеком — иначе провиснут у обоих.

## Пороговые сигналы

- Этап 1 растянулся сильно дольше плана → режем скоуп (реактивацию можно доделать при первом клиенте), но не откладываем продажи.
- 4 недели касаний после демо, < 2 платящих → менять сегмент или оффер, не наращивать спам.
- Внедрения покупают, абонентку нет → переупаковать сопровождение: кабинет + отчёт в рублях как «страховка».
- 3+ клиента просят одно и то же → в продукт (общий код), а не кастом за доплату.
