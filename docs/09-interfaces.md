# Интерфейсы: Telegram-бот, MAX-бот, CRM

Три поверхности продукта. Боты общаются с клиентом салона, CRM — с владельцем салона и с нами.

---

## 1. Боты (Telegram и MAX)

Логика диалога общая (`dialogs.py`), различаются только адаптеры каналов. Всё, что описано ниже, работает одинаково в обоих мессенджерах.

### Точки входа

| Как клиент попадает в бота | Что происходит |
|---|---|
| QR-код на стойке / зеркале | `/start` → приветствие + меню |
| Ссылка в шапке профиля салона | то же |
| Ссылка из SMS-волны реактивации | `/start` с параметром → бот сразу знает, кто это, и связывает `phone` → `tg_id`/`max_id` |
| Ссылка из напоминания | открывает конкретную запись |

Deep link: `t.me/salon_anna_bot?start=c_10482` — параметр несёт id клиента, чтобы не спрашивать телефон повторно.

### Главное меню

- Записаться
- Мои записи
- Перенести / отменить
- Вопрос администратору
- Отписаться от напоминаний (обязательный пункт)

### Сценарий записи (конечный автомат)

```
START → выбор услуги → выбор мастера (или «любой») → выбор дня
      → выбор времени → [если новый клиент: имя, телефон]
      → подтверждение → ЗАПИСАН
```

- Услуги, мастера, дни, время — inline-кнопки, состояние едет в `callback_data`.
- Имя и телефон — свободный ввод, состояние в таблице `dialog_state`.
- Телефон запрашиваем кнопкой «поделиться контактом» (в TG — `request_contact`), иначе текстом с валидацией.
- Свободные окна считаются на лету: рабочие часы салона минус занятые слоты минус длительность услуги.
- Если желаемого времени нет → предложение встать в лист ожидания (`waitlist`).
- После записи: подтверждение клиенту + уведомление админу салона в его личный чат с ботом.

### Сценарий напоминания

За 24 ч и за 2–3 ч до визита — сообщение с тремя кнопками:

| Кнопка | Что делает система |
|---|---|
| Приду | `bookings.status = confirmed`, больше не беспокоим |
| Перенести | запускает выбор нового времени, старый слот освобождается и уходит в лист ожидания |
| Отменить | слот освобождается, рассылка предложения листу ожидания, первый нажавший забирает |

Если ни одна кнопка не нажата за 2–3 часа → следующий канал по приоритету салона, дальше SMS. Каскад строится на «не подтвердил», а не «не прочитал» — read-статусов у бот-API нет.

### Сценарий реактивации

Персональное сообщение: имя, услуга, сколько прошло, ближайшее свободное окно, кнопка «Записаться». Внизу всегда «Больше не присылать» → `customers.do_not_disturb = true`.

### Вопрос администратору (FAQ)

Свободный текст, не подходящий ни под один шаг → LLM отвечает по базе знаний салона. Не уверен → «уточню у администратора» + тикет админу. ПДн в промпт не попадают.

### Различия между каналами

| | Telegram | MAX |
|---|---|---|
| Токен | @BotFather | @MasterBot |
| Вебхук | `/webhook/tg/<salon>` | `/webhook/max/<salon>` |
| Особенности | request_contact, deep links | сертификат Минцифры на сервере, лимит 30 rps |
| Публикация | сразу | верификация (самозанятости достаточно) |

Бот не может написать первым тому, кто не запускал бота — ни в TG, ни в MAX. Холодная база достижима только по SMS.

## 2. CRM: кабинет владельца салона

Роль `owner`, видит только свой `salon_id`. Вход по email + паролю на `app.домен.ru`.

### Дашборд

Метрики за текущий месяц: записей всего, подтверждено, неявок, **возвращено ≈ N ₽** (акцентная карточка — это главный экран продукта). Ниже — записи на сегодня и завтра со статусами:

| Статус | Значение |
|---|---|
| Придёт | клиент нажал «Приду» |
| Ждём ответ | напоминание отправлено, реакции нет |
| Из листа ожидания | окно освободилось и было перепродано |
| Отменил / Перенесена / Неявка | итоговые статусы |

### Записи

Список и календарь, фильтры по дате/мастеру/статусу. Кнопка «Добавить запись» — для телефонных обращений: админ салона вносит вручную, и запись попадает в тот же каскад напоминаний. Карточка записи: клиент, услуга, мастер, история сообщений по этой записи, ручная смена статуса.

### Клиенты

Таблица: имя, телефон, каналы (есть ли TG/MAX), последний визит, последняя услуга, метка «спящий». Фильтр «спящие» = кандидаты на реактивацию. Действия: исключить из рассылок, посмотреть историю визитов и сообщений.

### Сообщения

Журнал отправленного: канал, тип (напоминание / реактивация / подтверждение), статус доставки, стоимость. Счётчик расхода SMS против месячного лимита — прозрачность, чтобы не было споров по счетам.

### Отчёты

Архив месячных отчётов + текущий в реальном времени. Формула расчёта показывается открыто: сколько подтверждений, какой коэффициент неявок принят, какой средний чек. PDF на скачивание.

### Настройки

Услуги (название, цена, длительность, цикл повтора), мастера, часы работы, за сколько часов напоминать, тексты сообщений, приоритет каналов, средний чек для расчёта отчёта.

## 3. CRM: наша админка

Роль `superadmin`, видит все салоны.

### Список салонов

Таблица: название, статус (внедрение / активен / приостановлен), последняя активность бота, ошибки интеграций за сутки, расход SMS против лимита, дата следующего платежа.

### Онбординг нового салона

Одна форма: название, токены ботов (TG и/или MAX), средний чек, часы работы, приоритет каналов. По сабмиту система создаёт салон, регистрирует вебхуки, заводит дефолтные тексты и заготовки услуг, создаёт учётку владельца. Цель — 15 минут вместо копирования сценариев руками.

### Мониторинг и логи

Ошибки по салонам (упавший вебхук, отказ SMS-шлюза, недоступный YCLIENTS), лог сообщений с фильтрами, feature-флаги по салонам (у кого включена реактивация, у кого MAX).

### Биллинг

Абонентка по салонам, перерасход SMS сверх лимита, статусы оплат, приостановка салона за неоплату (боты продолжают отвечать, рассылки останавливаются — мягкое отключение).

## Правила интерфейса

- Ничего не показываем владельцу, что он не может объяснить сам: каждая цифра кликается до списка записей, из которых она собрана.
- Ни одного экрана без ответа на вопрос «сколько я на этом заработал».
- Все действия, меняющие данные салона, пишутся в аудит-лог с автором.
- Проверка `salon_id` на каждом запросе API — не на фронте, а в бэкенде.
