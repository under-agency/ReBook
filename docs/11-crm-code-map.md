## Инварианты, которые нельзя нарушать

1. **`salon_id` только из сессии.** Чужой объект — 404, не 403. Тест
   `tests/test_tenant_isolation.py` обязан оставаться зелёным.
2. **Все сообщения — через `channels.send()`.** Прямые вызовы Telegram API мимо него
   ломают журнал сообщений, лимиты SMS и отчёт.
3. **Время в БД — только `timestamptz` в UTC.** Конвертация в пояс салона — на границах:
   расчёт слотов, отображение, границы месяца в отчёте.
4. **Статусы `reminded_*` ставит только система** (`set_status(..., by_system=True)`).
   Владелец выставляет вручную только итоговые статусы.
5. **Деньги — `Decimal`/`numeric`,** никаких `float` в расчётах.
6. **Списки фильтруются и пагинируются в SQL,** а не в Python: иначе на базе
   в несколько тысяч строк каждый запрос тянет её целиком.
7. **Статус клиента считается дважды** — в Python (`computed_status`) и в SQL
   (`status_expression`). Меняя одну ветку, меняйте вторую; расхождение ловит
   `tests/test_customer_status.py`.
8. **Создание записи берёт advisory-lock** на (салон, мастер, день). Без него два
   клиента занимают один слот — это воспроизводится тестом
   `tests/test_concurrent_booking.py`.

## Как продолжить работу

Целевая платформа — Ubuntu Server 22.04/24.04.

```bash
sudo ./scripts/setup.sh                    # первичная установка: Postgres, Python, Node, схема, сиды
./scripts/dev.sh                           # бэкенд :8000 + кабинет :5173 + бот с воркером
cd apps/backend && ./.venv/bin/python -m pytest   # 50 тестов
```

Отдельные части: `./scripts/dev.sh backend|web|bot`.

Схему меняем через Alembic: правим `app/models.py`, затем
`alembic revision --autogenerate -m "что изменили"` и `alembic upgrade head`.

Демо-данные пересоздаются `./.venv/bin/python -m app.seed --reset`.

Боевое развёртывание (Docker Compose + Caddy с HTTPS, бот отдельным контейнером) —
`deploy/README.md`. Бэкапы и регламент проверки восстановления — `ops/`.
