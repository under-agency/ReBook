# Техническая архитектура

## Принципы

1. **Ноль лишних затрат на старте** — self-hosted, легковесный Python-стек, бесплатные каналы, платим только за VPS и SMS.
2. **Модульность и конфигурации** — подключение нового клиента = конфигурационный файл/база + токен бота, без переписывания кодовой базы.
3. **Надежность как фича** — изоляция клиентов, мониторинг (Healthcheck / Telegram Alerts), автоматические бэкапы. «Бот не ляжет в субботу вечером» — часть ценностного предложения.

## Схема

```text
Клиент заведения                   Владелец / Администратор
     │                                        ▲
     ▼                                        │ отчёты, уведомления
Telegram-бот ◄──────────┐                     │
     │                  │                ┌────┴────────┐
     ▼                  │                │   Python    │
┌──────────────────────────────────────► │  Сервисы    │
│  Модули сценариев (Python Service)     │  (Docker /  │
│  • онлайн-запись                       │   systemd)  │
│  • каскад напоминаний                  └────┬────────┘
│  • реактивация базы                         │
└───────┬───────────┬───────────┬─────────────┘
        ▼           ▼           ▼
   YCLIENTS /   SMS-шлюз    LLM (OpenRouter)
   amoCRM /                 для свободных
   Google Sheets            вопросов
```

## Компоненты

### Ядро — Python Backend (Docker / systemd)

- VPS в РФ (~300–600 ₽/мес), контейнеризация Docker.
- Асинхронный/детерминированный стек: Python 3, `pyTelegramBotAPI`, PostgreSQL / SQLite, `gspread`.
- Изолированные сервисы: приём записи, планировщик напоминаний (APScheduler / Celery / cron), генерация ежемесячных отчётов.

### Каналы коммуникации

- **Telegram Bot API** — основной канал: бесплатный, мгновенный отклик, инлайн-кнопки, работа через Long Polling или Webhooks. У каждого клиента свой брендированный бот.
- **SMS** — догон для тех, кто не ответил в Telegram (SMS Aero / SMSC). Единственная переменная себестоимость.
- **WhatsApp** — только официальный Cloud API по запросу клиента (неофициальные библиотеки не используются во избежание банов).

### Интеграции с системами учета

Приоритет по частоте у целевой аудитории:

1. **Google Sheets API** — MVP-вариант для клиентов без CRM: расписание и база клиентов в таблице.
2. **YCLIENTS API** — салоны красоты и автосервисы. Проверка доступности API на тарифе заказчика до интеграции.
3. **amoCRM API** — для клиентов с развитыми отделами продаж.
4. Позже: IDENT и МИС для медицинских центров и стоматологий.

### LLM-слой (AI-ассистент)

- Провайдер OpenRouter; быстрые и экономичные модели.
- Используется **исключительно** для обработки свободных вопросов клиентов («есть ли парковка?», «можно ли с собакой?») по локальной базе знаний.
- Запись, выбор времени и напоминания — строгие детерминированные кнопочные сценарии.
- Фолбэк: при неуверенном ответе бот переводит диалог на живого администратора с алертом в рабочий чат.

## Безопасность

- Сервера и базы данных физически расположены в РФ (соответствие 152-ФЗ).
- Изоляция данных клиентов: раздельные токены, переменные окружения и права доступа.
- Секреты хранятся в `.env` / защищенных переменных окружения, а не в коде.
- Автоматические ежедневные бэкапы баз данных и файлов конфигураций на независимое хранилище.
- Мониторинг: непрерывный healthcheck и мгновенные алерты в Telegram при любых сбоях.

## Тиражирование и онбординг

Подключение нового клиента по регламенту (цель $\le 2$ часов работы):

1. Регистрация Telegram-бота в BotFather и получение токена.
2. Создание конфигурации заведения (услуги, цены, длительность, шаблоны текстов).
3. Подключение источника расписания (Google Sheets / YCLIENTS / amoCRM).
4. Прогон тестового цикла: бронирование $\rightarrow$ получение напоминания $\rightarrow$ проверка записи в таблице.
5. Включение сервиса в реестр мониторинга.

## Демо-стенд

Интерактивный демонстрационный бот с типовым заведением (3–4 услуги, расписание слотов): потенциальный клиент за 30 секунд самостоятельно оформляет запись и через минуту получает проверочное напоминание.
