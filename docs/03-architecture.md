# Техническая архитектура

## Принципы

1. **Ноль лишних затрат на старте** — self-hosted, бесплатные каналы, платим только за VPS и SMS.
2. **Шаблон, а не заказная разработка** — подключение нового клиента = копия воркфлоу + конфиг, а не новый проект.
3. **Надёжность как фича** — мониторинг, бэкапы, изоляция клиентов. «Бот не ляжет в субботу вечером» — часть оффера.

## Схема

```
Клиент салона                      Владелец/админ
     │                                   ▲
     ▼                                   │ отчёты, уведомления
Telegram-бот ◄──────────┐                │
     │                  │           ┌────┴─────┐
     ▼                  │           │  n8n     │
┌─────────────────────────────────► │ (VPS,    │
│  Ядро сценариев (n8n workflows)   │ self-    │
│  • запись                         │ hosted)  │
│  • каскад напоминаний             └────┬─────┘
│  • реактивация                         │
└───────┬───────────┬───────────┬────────┘
        ▼           ▼           ▼
   YCLIENTS /   SMS-шлюз    LLM (OpenRouter)
   amoCRM /                 для свободных
   Google Sheets            вопросов
```

## Компоненты

### Ядро — n8n (self-hosted)

- Дешёвый VPS в РФ (~300–600 ₽/мес), Docker.
- Один инстанс, воркфлоу клиентов разделены по неймингу и креденшелам; при росте — по инстансу на пул клиентов.
- Все сценарии: приём записи, каскад напоминаний, реактивация, генерация отчёта.

### Каналы

- **Telegram Bot API** — основной канал: бесплатный, кнопки, вебхуки. У каждого клиента свой бот (свой токен) — брендирование и изоляция.
- **SMS** — догон для тех, кто не прочитал Telegram (SMS Aero / SMSC и т.п.). Единственная переменная себестоимость.
- **WhatsApp** — только официальный API и только если клиент готов платить за него; неофициальные библиотеки не используем (баны). На старте — нет.

### Интеграции с учётными системами

Приоритет по частоте у ЦА:

1. **Google Sheets** — MVP-вариант для клиентов без CRM: расписание и база в таблице.
2. **YCLIENTS API** — салоны/автосервисы. ⚠️ Проверять доступность API на тарифе клиента ДО обещания интеграции.
3. **amoCRM** — у кого продажи в CRM.
4. Позже: IDENT и МИС для стоматологий.

### LLM-слой

- OpenRouter как провайдер; модель — дешёвая и быстрая.
- Используется ТОЛЬКО для свободных вопросов («а можно с ребёнком?», «есть ли парковка») по базе знаний клиента. Запись, напоминания, реактивация — детерминированные кнопочные сценарии, LLM там не нужен и вреден (непредсказуемость).
- Фолбэк: LLM не ответил уверенно → «передал администратору», тикет админу в Telegram.

## Безопасность (зона ИБ-партнёра)

- Данные и VPS — в РФ.
- Изоляция клиентов: отдельные боты/токены/креденшелы, доступ к данным клиента только из его воркфлоу.
- Секреты — в n8n credentials, не в коде сценариев; ротация при офбординге клиента.
- Ежедневные бэкапы (конфиг n8n + данные) на отдельное хранилище.
- Мониторинг: healthcheck воркфлоу, алерт в наш Telegram при падении вебхука/интеграции — чиним раньше, чем заметит клиент.
- Минимизация ПДн: храним только нужное для сценариев (имя, телефон/tg id, история визитов); в LLM персональные данные не отправляем (вопросы FAQ их не требуют).

## Шаблонизация (ключ к масштабу)

Онбординг нового клиента — по чек-листу, цель ≤ 2 часов техработы:

1. Создать Telegram-бота, вписать токен.
2. Скопировать шаблонные воркфлоу, подставить конфиг (услуги, цены, циклы услуг, тексты).
3. Подключить источник расписания (Sheets / YCLIENTS / amoCRM).
4. Прогнать тестовый сценарий записи и напоминания.
5. Включить мониторинг и добавить в реестр клиентов.

Все тексты и параметры — в конфиге, не зашиты в сценарии: правки без программирования.

## Демо-стенд

Отдельный бот с фиктивным салоном (3–4 услуги, живое расписание): владелец записывается сам за 30 секунд и через минуту получает «напоминание». Продаёт лучше презентации.
